EduTrack - Student Management System

A live, in-browser simulation of the EduTrack console application. Drive the same menu, prompts and validation as the real Python + MySQL program, watch each workflow execute step by step, and see the exact SQL every action runs.

What the workflow demonstrates

Each menu action runs the same logic as the real application.

  1. 1
    Add StudentCollects 11 validated fields (name, gender, DOB, class, section, roll no, email, phone, address, admission date), then runs an INSERT.
  2. 2
    Search by Roll NumberFinds one record with SELECT ... WHERE roll_no = %s and prints the profile card.
  3. 3
    Search by Student IDPrimary-key lookup, same profile view, keyed on the auto-increment ID.
  4. 4
    View All StudentsLists every row as a profile card.
  5. 5
    Update StudentShows current details, re-collects all fields, then runs an UPDATE.
  6. 6
    Delete StudentShows the record, asks for a Y/N confirmation, then runs a DELETE.
  7. 7
    ExitCloses the console gracefully; the demo simply restarts it.

Behind the scenes

The real app (Python + mysql-connector-python) runs these prepared statements against MySQL through a repository layer:

-- database/schema.sql -> students table INSERT INTO students (first_name, last_name, gender, dob, `class`, section, roll_no, email, phone, address, admission_date) VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s); SELECT * FROM students WHERE roll_no = %s; SELECT * FROM students WHERE student_id = %s; SELECT * FROM students; UPDATE students SET first_name = %s, ..., admission_date = %s WHERE student_id = %s; DELETE FROM students WHERE student_id = %s;

Records are saved in localStorage, so they survive a page refresh. Type reset at the prompt to restore the sample data. Validation rules (positive integers, email and phone patterns, gender choices, YYYY-MM-DD dates, unique roll numbers) mirror input_validators.py, and constraint violations are reported the way the real app reports database errors.
